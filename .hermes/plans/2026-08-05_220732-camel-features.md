# CAMEL Features no Aegis — Plano de Implementação

> **Contexto:** usuário pediu "coloque features do camel" — trazer recursos do
> framework [camel-ai/camel](https://github.com/camel-ai/camel) (instalado em
> `~/git_repos/camel`, container `camel-localdev`) para o **Aegis**. Decisão do
> usuário: **TUDO junto** (roles + memória pontuada + toolkits), port **nativo**
> (SEM dependência do pacote `camel-ai`), testes **offline**. Estado atual: apenas
> este plano salvo — nada de código foi alterado ainda.

**Goal:** adicionar ao Aegis três famílias de features inspiradas no CAMEL —
(1) role-playing/personas + especificação de tarefa, (2) memória pontuada por
importância com recuperação heurística top-k, (3) toolkits novos
(thinking / task-planning / note-taking).

**Arquitetura:** port nativo em módulos novos, seguindo os padrões já existentes
do projeto (ferramentas `@tool` file-based como `aegis/tarefas.py`; persistência
em `config/dados/*.json`; env `AEGIS_*`). Sem alterar o grafo nem o núcleo
LangGraph — só registrar ferramentas e injetar contexto no prompt.

**Tech Stack:** Python 3.11 (Pixi), LangGraph, langchain `@tool`, pytest (offline),
JSON em `config/dados/`. Nenhuma dependência nova.

## Feature 1 — Roles / role-playing + especificação de tarefa

### 1.1 `aegis/papeis.py` (novo) — núcleo de papéis
- `Papel` (`@dataclass`): `nome`, `descricao`, `identidade` (persona/prompt),
  `ferramentas_focadas: list[str] = field(default_factory=list)` (sugestão, não hard),
  `instrucoes: str = ""`.
- `PAPEIS_PADRAO: list[Papel]`: `assistente` (default), `pesquisador`, `redator`
  (reusa as personas de `prompts.py::sistema_pesquisador/redator`), `planejador`.
- `carregar_papeis(caminho_json=None) -> list[Papel]`: merge dos padrões com um
  JSON opcional `config/dados/papeis.json` (formato `[{"nome":..., "identidade":...}]`).
- `resolver_papel(nome, papeis=None) -> Papel`: match exato/insensível a caixa;
  lança `ValueError` se inexistente.
- `montar_identidade(papel) -> str`: trecho de prompt (injetável).

### 1.2 `aegis/papeis.py` — ferramentas `@tool`
- `definir_papel(nome: str) -> str`: valida por `resolver_papel`; grava
  `config/dados/papel_ativo.json` `{"nome":..., "identidade":...}` (padrão `tarefas`).
- `ver_papel() -> str`: lê o ativo (ou "(nenhum)").
- `listar_papeis() -> str`: catálogo `nome — descricao`.

### 1.3 Especificação de tarefa (TaskSpecifyAgent)
- `especificar_tarefa(objetivo: str, restricoes: str = "", criterios: str = "") -> str`:
  grava `config/dados/tarefa_atual.json` como cartão estruturado
  `{"objetivo","restricoes","criterios","ts"}`.
- `estruturar_tarefa(texto_livre: str) -> dict` (função PURA, testável offline):
  faz parse determinístico (quebra por linhas separadas por `;`/`-`) e retorna cartão.
- Injeção: `prompts.py::sistema()` adiciona seção `## Papel ativo` (se `papel_ativo.json`
  existir) e `## Tarefa especificada` (se `tarefa_atual.json` existir). Funções puras
  auxiliares `_ler_arquivo_json(caminho)` com path injetável p/ teste.

**Arquivos:** criar `aegis/papeis.py`; modificar `aegis/prompts.py` (injeção),
`aegis/ferramentas/__init__.py` (registro). Testes `tests/test_papeis.py`,
`tests/test_prompts_camel.py`.

## Feature 2 — Memória pontuada (style CAMEL `MemoryRecord`)

### 2.1 `aegis/memoria_camel.py` (novo)
- `RegistroMemoria` (`@dataclass`): `id`, `conteudo`, `importancia: float` (0–10),
  `ts: float`, `fonte: str = "agente"`.
- `pontuacao(registro, consulta, peso_importancia=1.0, meia_vida=... ) -> float`:
  **heurística determinística** (testável offline), soma de:
  - **recência** = `exp(-(agora - ts) / c)` (decay exponencial),
  - **importância** = `peso_importancia * (consulta_importancia / 10)`,
  - **similaridade lexical** = overlap de tokens `consulta ∩ conteudo` normalizado
    (no lugar de embedding; offline).
- `RecuperadorTopK`: `selecionar(consulta, k=3) -> list[RegistroMemoria]` ordenadas
  por `pontuacao` desc.
- Persistência: `carregar_memoria(caminho=None)` / `salvar_memoria(registros, caminho=None)`
  em `config/dados/memoria_pontuada.json`.

### 2.2 Ferramentas
- `registrar_memoria_camel(conteudo: str, importancia: float = 5.0, fonte: str = "agente") -> str`
  — cria `RegistroMemoria` e persiste.
- `consultar_memoria_camel(consulta: str, k: int = 3) -> str` — top-k por `selecionar`
  (menino CAMEL `retrieval`).

**Arquivos:** criar `aegis/memoria_camel.py`; registro em `ferramentas/__init__.py`;
testes `tests/test_memoria_camel.py`.

## Feature 3 — Toolkits CAMEL (thinking / task-planning / note-taking)

Novo módulo `aegis/ferramentas/camel_kit.py` (padrão `basicas.py`), todas `@tool`, file-based:

- `pensar(passo_raciocinio: str) -> str` — **ThinkingToolkit**: append de passo a
  `config/dados/pensamento_atual.json` (lista); retorna os passos acumulados numerados.
  Cotexo de raciocínio estruturado.
- `planejar_tarefa(objetivo: str, passos: list[str]) -> str` — **TaskPlanning**:
  cria `config/dados/plano_tarefas.json` `[{id, passo, status:"pendente"}]`.
- `atualizar_plano(id: str, novo_status: str) -> str` — marca passo (`pendente/executando/ok`).
- `ver_plano() -> str` — lista plano com progresso.
- `anotar(nota: str) -> str` — **NoteTaking**: append `config/dados/notas.json`
  `[{ts, nota}]`.
- `ver_notas() -> str` — lista as últimas N notas.

**Arquivos:** criar `aegis/ferramentas/camel_kit.py`; registro em `ferramentas/__init__.py`;
testes `tests/test_camel_kit.py`.

## Riscos / tradeoffs / pendências

- **Riscos:** nenhuma dependência nova (port nativo). Ferramentas file-based seguem o
  padrão `tarefas` (sem tocar o grafo). Injeção de prompt só se evento arquivo existir
  (fallback seguro). `escrever_tarefa`/`estruturar_tarefa` são puras (testáveis offline);
  caminho automático no grafo fica como evolução futura.
- **Aberto (pergunte ao implementar/se precisar):**
  1. Memorão pontuada deve reusar a Store de longo prazo `("aegis", ...)` em vez de JSON
     próprio? (decidido: JSON próprio p/ simplicidade; pode migrar depois).
  2. Papel ativo deve ser global (todos) ou por thread (`thread_id` no nome do arquivo)?
     Default: por todo o arquivo `papel_ativo.json` (global), simples.
  3. `especificar_tarefa` automática (nó no grafo) vs só ferramenta sob demanda? Proposta
     inicial: **só ferramenta** (YAGNI); o nó pode ser evolução.

## A4.1 — Features científicas (`aegis/cientificas.py`, novo)

Vida acadêmica do Aegis — busca e organização de literatura. Sem dependência nova

- `ler_resumo(arxiv_id: str) -> str` — retorna o resumo de um paper já na biblioteca

- `salvar_paper(paper) -> str` — grava na biblioteca `config/dados/biblioteca.json`

## A4.2 — Banco estilo Obsidian (`aegis/obsidian.py`, novo)

Um "vault" de conhecimento local, espelhando o modelo do Obsidian: **cada nota = 1
arquivo `.md`**, com links bidirecionais `[[Nome da Nota]]`, pastas e tags. NÃO é um
SQLite relacional — é um banco de arquivos markdown com índice, como o Obsidian faz.

- Vault em `config/dados/obsidian/` (default, env `AEGIS_OBSIDIAN_DIR`), subpastas livres.
- **Wikilinks/backlinks:** ferramenta de índice `config/dados/obsidian/indice.json`
  (mapa `nota -> [[links]]`) atualizado a cada escrita → permite **backlinks** (`quem
  me cita`) e o **grafo de conexões** (objetos conectados).
- Tools (`@tool`, file-based):
  - `criar_nota(nome, conteudo, pasta="") -> str` — cria `.md`; extrai `[[links]]` e
    backlinks; se `nome` já existe, anexa/sobrescreve (decidir: sobrescrever, avisando).
  - `ler_nota(nome) -> str` — conteúdo markdown.
  - `ligar_nota(de, para) -> str` — adiciona `[[para]]` em `de` (link direto).
  - `buscar_notas(palavra) -> str` — full-text simples (nome + corpo) → lista de notas.
  - `notas_por_tag(tag) -> str` — filtra por `#tag` no corpo.
  - `notas_conectadas(nome) -> str` — forward links + backlinks (grafo vizinhos).
  - `listar_obsidian() -> str` — árvore `pasta/arquivo` + contagem de notas.
  - `limpar_obsidian(confirmar) -> str` — remove o vault (guard opcional).
- Tags: `#ciencia #vida #projeto` (parse simples por regex).
- Testes `tests/test_obsidian.py` (`tmp_path`, `monkeypatch` do dir):
  criar/ler nota · email links `[[x]]` → `indice` atualizado · backlink (`b` cita,
  `a` aparece em `notas_conectadas(b)`) · busca full-text · tag · árvore/listar ·
  carga de índice (roundtrip). ~10 casos.

> Motivo de "db parecido com obsidian": interoperar com um vault real do User
> (ex.: `~/progects`/`~/Obsidian`) e dar ao agente a mesma semântica de conhecimento
> bidirecional. Pode ler vaults existentes apontando `AEGIS_OBSIDIAN_DIR` p/ um repo
> de notas (futuro: ver se o usuário tem vault; não hoje).
